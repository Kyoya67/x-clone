# Design Doc

## 1. 開発方針

詳細な設計を最初に固定せず、最小限の全体像を定めたうえで、機能単位に実装と検証を繰り返す。

まずフロントエンド、バックエンド、データベースをつなげた最小の経路を作り、その後、機能や品質を段階的に追加する。

設計上の判断は、実装や検証の結果に応じて見直す。変更した場合は、その理由とトレードオフを記録する。

### Issueの管理方針

作業はGitHub Issueで管理する。目的、完了条件、検証結果、次に残る課題を記録する。

最初にすべての作業を詳細化するのではなく、直近の作業に必要なIssueを作成する。実装と検証の結果に応じて、次のIssueの内容や優先度を見直す。

Issueの進捗はGitHub Projectsで管理し、Statusを用いて未着手・対応中・完了を把握する。
