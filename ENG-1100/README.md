# カミナシ - ソフトウェアエンジニア選考課題のご案内（カミナシ 設備保全）

## 課題

### 本課題の意図・位置付け

本課題は、候補者さまの技術力や知識だけではなく、 **技術的な思想や志向、当社とのマッチング** を確認させていただく目的で設定しております。

候補者様がどのようなソフトウェアエンジニアであるかを、課題を通して表現していただけると幸いです。

### 本課題で大切にしていること

生成AIの活用が当たり前になり、動くソフトウェアをある程度の完成度で仕上げること自体は、以前ほど難しくなくなりました。
本課題で見ているのは、実装の完成度だけではありません。

- **要件の外側**：ここに書かれているのは最低限の要件です。記載のない工夫や配慮を加えていただいて構いません。
- **理由の記録**：何を選んだかだけでなく、なぜその選択をしたのかも残してください。比較した案や、優先順位の付け方が伝わると助かります。
- **率直さ**：うまくいかなかったことや、時間の都合で見送ったことがあれば、隠さず書いてください。そうした記載はむしろ歓迎します。
- **利用者の視点**：このプロダクトを実際に使う人や、あとからチームに加わる人の立場に立って、アウトプットに向き合ってみてください。

AIの活用は歓迎します。
その上で、何をAIに任せ、何をご自身で判断したのかが伝わるようにしてください。

### 課題テーマ

X（旧 Twitter） のクローンアプリの開発

### 機能要件

本課題は、Twitter API クライアントの開発ではなく、サービスとしての Twitter のクローンを開発する課題です。以下の機能を実装してください。

1. ツイートする
1. 他ユーザーをフォローする
1. タイムラインを見る

上記要件を満たした上でのさらなる機能追加については、一切制約はございませんが、昨今 AI の活用が進んできたこともあり、ほとんどの候補者さまにとって、上記機能の実装に問題はないと思います。

### 非機能要件

1. Web フロントエンドは[TypeScript](https://www.typescriptlang.org), [React](https://react.dev)を利用して開発してください。
1. バックエンドは、[Go 言語](https://go.dev/)を利用して開発してください。
1. 3-6 名程度が所属するチームでアジリティ高く開発できそうか、新しいメンバーがシームレスに開発に参加できそうかを考慮した構成にしてください。
1. 普段の開発はチームに所属する各開発者の手元のラップトップで行えるようにしてください。
1. AWS に代表されるパブリッククラウドにデプロイして顧客提供できるように考慮してください。
1. よりよいユーザー体験、将来の拡張性、横断的な関心事（セキュリティやエラーハンドリング）を考慮してください

### 実装について

少なくとも以下の層に分けて開発を行ってください。

1. フロントエンドレイヤー
1. バックエンドレイヤー（API の設計を含む）

カミナシにはフロントエンドスキルを軸とするエンジニアやバックエンドスキルを軸とするエンジニアがいますが、普段の業務においては技術領域による担当範囲の制約は設けず、ディスカバリからデリバリまで、フロントからインフラまで、フルサイクルで開発する体制で開発を行っています。

そのため本課題でも、フロントエンドとバックエンドの両方を実装してください。
どちらのレイヤーにより注力するかは、ご自身の得意分野に応じて選んでいただいて構いません。

- 「フロントエンドレイヤー」については、TypeScript と React で実装してください。レンダリング方法は任意で、React のラッパーフレームワークや、UI ライブラリ、状態管理ライブラリなどは自由に採用して構いません。
- 「バックエンドレイヤー」については、非機能要件に記載のとおり Go 言語で実装してください。API の設計もこのレイヤーに含みます。公開 API として外部公開されることを前提とし、一般に浸透していると思われるスキーマ定義仕様やツール（OpenAPI, gRPC 等）を用いて設計・実装してください。プロダクションで動かすことを想定したクラウドインフラストラクチャのアーキテクチャについては、具体的な実装は不要です。簡単な文章や図での説明で済ませても構いません。

### Design Doc（必須）

本課題では、実装そのものに加えて **サービスの Design Doc の作成を必須** とします。形式は Markdown やその他ドキュメント形式で構いませんが、リポジトリに含めて提出してください。

Design Doc には、少なくとも以下の観点を含めてください。

- 要件の整理（本ガイドに明記されていない、ご自身で補った要件があればそれも含む）
- 検討したアーキテクチャ・実装方針の選択肢と、それぞれのトレードオフ
- 最終的に選んだ方針とその理由
- 今後の拡張性や運用を見据えた懸念点

### AI エージェントの活用について（推奨）

本課題への取り組みにあたり、Claude Code や GitHub Copilot などの AI コーディングエージェントを活用いただいて構いません。その際、`CLAUDE.md` や `AGENTS.md` といった設定ファイル、カスタム skill やその他の仕組みを構築された場合は、それらもあわせてリポジトリにコミットしていただくことを推奨します。

### 留意事項

1. `main` ブランチを使って動作確認いたします。 `main` 以外のブランチで開発作業を実施する場合、提出前にすべての成果物が `main` ブランチで正しく動作することをご確認ください。
1. コードやドキュメントの変更履歴も選考審査における重要な情報となります。普段のお仕事と同じく、候補者さまご自身の作業の流れが可能な限りそのままコミットログとして残る形で課題に取り組んでください。
1. AI の活用も問題ありません。活用時に留意したポイントや工夫したポイントなどあれば、ぜひドキュメントに残してください。
1. 動作確認も行う場合があります。
   - カミナシ社の評価者が動作確認を実施する際には、安全のため GitHub [Codespaces](https://github.co.jp/features/codespaces) を利用します。

もしも時間の都合上やり残したことがあるまま提出せざるを得ない場合は、ぜひそれらのやり残した事柄を GitHub issue 等 にご記載ください。参考にさせていただきます。

## 技術評価ポイント

**カミナシでは、最終的な提出物を通して、候補者さまの知識や経験だけでなく、こだわりや考え方を確認させていただこうと思っています**。

AI による実装が増えているため、単に動くものが作れているかだけでなく、実装内容や設計思想を重点的に確認しています。こだわりや哲学を、ぜひ実装にこめていただければ幸いです。

AI を活用される場合は、どのように活用したか、AI の提案を鵜呑みにせず検証・レビューした過程はなにか、AI に任せた部分と自分で判断した部分の切り分けなどを実装にこめてください。

## 課題提出期限

当社採用担当からの選考課題案内を起点として、おおむね **1 週間程度** での提出を目安としています。

普段のお仕事などと両立しながら課題に取り組んでくださっている候補者さまが多いため『1 週間程度』というのはあくまで目安となります。もし 1 週間を超えそうな場合も、どうぞお気軽にご相談ください。

課題に関するご質問は、当社採用担当までお気軽にご連絡ください。
